# PostAI — пакет исправлений №1

Подготовлен 16 ноября 2026. Основа — загруженный архив PostAI-Intel2-main, коммит a087174.
Это исходники для отдельной ветки и тестового развёртывания, не готовая подтверждённая production-установка.

## Что изменено

- Все личные API проверяют подпись и срок Clerk-сессии, origin (authorized party), session ID и подтверждённый основной email.
- Идентификатор владельца — Clerk user ID из проверенного токена; email из тела запроса не определяет доступ.
- Supabase используется только сервером с SERVICE_ROLE_KEY. Фильтрация владельца обязательна в серверном коде.
- Канал подтверждается случайным кодом в описании Telegram и проверкой прав бота. Старые записи сохраняются, но требуют подтверждения.
- Единый бесплатный лимит: **1 успешная генерация**, как в исходном предложении на сайте. Значение — `shared/config.js`.
- Upstash резервирует лимит атомарно до платного вызова; ошибка генерации возвращает резерв. Подтверждённый email учитывает старый usage-счётчик, старые ключи не удаляются.
- Убраны привилегии по email из тела запроса. Бывшие администраторы теперь подчиняются тому же бесплатному лимиту.
- Есть ограничения частоты генераций, публикаций, добавления каналов и подбора ключевых слов.
- Готовый текст планируемого поста сохраняется; язык и параметры регулярной генерации сохраняются.
- Обработчик очереди захватывает одну запись условным UPDATE, что защищает от двух одновременных отправок одного задания.
- Повторное задание получает следующую дату; пропущенные слоты не догоняются пачкой.
- Неопределённый исход отправки становится `unknown`, без автоматической повторной отправки.
- Исправлен синтаксис keywords.js. Старый HTML-планировщик и ручной increment отключены.
- Публичный Clerk-ключ перенесён в переменную окружения; сборка без него останавливается.
- Сохранённое согласие на аналитику восстанавливается при следующем визите.

## Что в пакет не входит

- Оплата, платные квоты, подписки, возвраты и управление тарифами. Кнопки платных тарифов пока ведут в Telegram, как раньше.
- Перенос Development-пользователей в новую Clerk Production instance. При смене instance меняются user ID и нужна отдельная миграция.
- Настройка внешнего частого планировщика. В `vercel.json` оставлен совместимый с Hobby cron 09:00 UTC раз в сутки.
- Обновление устаревших основных зависимостей: оно должно идти отдельным проверяемым шагом.
- Замена старой интеграции изображений `source.unsplash.com`, полноценная история постов, кабинет подписки и расширение SEO-страниц.

## Ограничения очереди

Один запуск обрабатывает **один пост**. При Hobby cron — максимум один пост в сутки, без точности до выбранной минуты.
Для запуска продукта с отложенными постами нужно подключить защищённый вызов обработчика каждую минуту и нагрузочно проверить пропускную способность.
Секрет передаётся только в HTTP-заголовке Authorization; endpoint не принимает секрет в URL.
Публикация только в Telegram; Instagram/Facebook остаются направлениями генерации текста.
Текст отправляется без Markdown-разметки, до 4096 символов; длинные тексты не режутся и не отправляются частично.

## Локальный запуск

Node.js 22 LTS рекомендуется для воспроизводимости. Выполнить `npm ci`, создать `.env.local` по `.env.example`.
`npm test` запускает локальные тесты; `npm run build` проверяет интерфейс.
Обычный `npm run dev` запускает только Vite: API Vercel он не обслуживает. Для полного сценария нужен тестовый Vercel deployment либо настроенный `vercel dev`.
